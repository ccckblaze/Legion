# AC922 · 深窗请求池（budget 准入）评估 — 2026-11-28

配套前篇 `ac922-decode-window-anatomy.md`。数据：runbook §414/§417/§418（同文/异源/满窗三把尺，
`reburst_steady.py` / `reburst_div.py`，全部 strict-fairness 带内）。

## 一、为什么需要它（三条实测事实）

1. **深窗聚合有悬崖**：4×V100 UD 道，满窗 262144 异源并发
   （每路 tg）：C1 28.7 → C2×2 行 15.8-17.6（agg **31.5**，峰值）→ 第 3 行进入即 **1.5**
   （agg 4.45，−91%@每路）。悬崖位于常驻 (524288, 786432] token 区间；`expert cache lent
   device=*` 与塌缩同步，host-tier 预算恰 3×262144 被穿是首要嫌疑。
2. **现状准入是"赛跑后拒单"**：`lm.rs` 的 decode-state 装配按**瞬时空闲 VRAM** 判定
   （"the decode state does not fit"→ HTTP 400），与 lend 时序竞争——同形态负载 C2 拒 1 行、
   C3 反而跑 2 行，结果不可复现。400 是纯损失：既不排队也不腾挪。
3. **异源多智能体是常态负载**：同文（前缀共享）尺只是上限口径；异源 C4@123K 聚合只有 12.4
   （每路 3.2），且与 KV 深度强相关——调度层必须在"进多少行"这一维度上加闸。

## 二、设计（三要件，全部在引擎外圈+队列层）

- **预算准入** `--resident-window-budget <tokens>`（建议默认 **2×满窗**，本机 524288）：
  新请求进窗前校验 `Σ(运行中行当前窗口) + 新请求全长 ≤ budget`；超预算**排队等待**而非 400。
  400 仅保留 prompt>ctx-size 的真超限。预算即"真实 VRAM 上限"的调度学代理：
  本机 2×满窗 = 每 GPU 常驻 ~261K 的池恰好被 2 行瓜分，3 行起必穿。
- **合并调度（小请求填缝）**：`queue.rs` pick 时按剩余预算 bin-pack：小窗口请求优先塞进
  大请求之间的空隙，正对"总窗口不变、多跑短任务"的诉求；与既有 fair-share（key 维度）
  正交可叠加。
- **防饿死（保护机制）**：等待超 T（建议 90 s 或 N 轮 pick）的请求升级为独占候选：
  暂停接纳新行，让它在当前行排空后整窗进窗。引擎 #1159 的 lend 语义（running 优先、
  idle-warm 让位 host tier）已提供腾挪原语，不需要新 eviction。

**质量中性论证**：只改"何时进窗"，不改任何行的数值路径（同窗内容、同 step 数学）；
验收 det 快扫即可，无需 quant_quality/divprobe。

## 三、收益与代价

- 深饱和满窗档（C4 需求）：现状 agg 4.45 + 1×400 → 预算准入后理论 ~31.5 + 排队行随后
  消化（**≈7×**，取 §418 C3 实跑 2 行值为证）。
- 混合负载（1 满窗 + N 小窗）：小窗不再被大窗 lend 风暴波及——这是多智能体日常形态。
- 代价：深窗请求 P99 延迟上升（排队可见化）；budget 配错（>2×满窗）会退化成现状。
  需要 `lane.sh status` 增加 budget/排队长度自述行。

## 四、实施顺序

1. P0（零码）：生产 `--kv-host-tokens` 从 786432 提到 ≥4×满窗（若 RAM 允许），观察 C3/C4
   悬崖是否右移——钉死"host-tier 被穿"假设。
2. P1：queue.rs 预算准入 + 排队（不动数值路径）；防饿死先用固定 T。
3. P2：bin-pack 填缝 + 悬崖二分（524288+64K/+128K）定最终默认 budget。
4. P3：与 conv-tier 记账/驱逐（128 GiB 帽）联动，复活链走同一预算口径。

## 五、开放问题

- 悬崖机制未钉死（host-tier 穿线 vs 每步全行专家重流 vs lend 抖动），P0 实验即裁决。
- 123K 档预算等价点未测（4×140K=560K 已在塌缩前夜）。
- `--scheduling-policy priority` 与本预算准入的组合语义需先读 `queue.rs` 合并规则
  （classes_of_two_queues_merge_by_priority 已给出先例）。

## 六、落地状态（2026-11-28，4×V100 卡 0/1/3/4）

- **P1 已上线并实测**（`1631acf` + `b2e7d8e`）：`queue.rs` 的 `Fit{Fits,Blocked,Starved}` 与
  `pop_fit()` 只过滤候选、不改 policy 排序；准入环按 `Seq::window` 求和加新请求
  `min(prompt+max_tokens, ctx)` 计窗，超预算排队重试，`--resident-window-starve`（默认 **600 s**：
  90 s 的兜底在 456 s 的 fill 波内必被穿光，budget 形同虚设）强制进窗保活性，被抢占行永不
  `Blocked`。默认 `budget=0` = 与旧版逐字节一致。
- **收益（wb4-c4，`reburst_div 262144 4`）**：聚合 **4.45 → 27.28 rows/s（6.1×）**，每路
  `tg_med` **1.5 → 15.0**（min 9.1 / max 16.9），逼近 §418 的甜点 31.5。排队可见：
  `queue_ms` 最长 186 s，无塌缩。
  **（§421 翻案：此账作废）** 复测证明 27.28 主要来自盘态（冷层已预热/链未被剪），不是预算的
  效果：空冷层同形配对 FA(budget on)/BG(off) = **5.93 vs 21.01** agg，CTL 复验 20.25。
  预算在"均匀 4×满窗"上买到的是**每行速率的确定性与不塌缩**（在窗 15-32 vs 无预算 4 行时的
  1.48-1.53），聚合反而因切波次+排队受损；该档聚合天花板 ~20-30 由 sm70 带宽给定。
- **混尺寸档（已证实的正收益，`reburst_mix 262144,65536,65536,65536`）**：窗口和 458752 ≤
  524288 预算时四行同窗并发，引擎 decode 19.3/20.2/25.9/25.9，**agg ≈ 51.5**，0 errs。
  **"窗口和 ≤ 2×满窗，并发几乎免费"** 是多智能体日常形态（一长带数短）的直接依据。
- **量尺登记**：`reburst_div` 的整除分片会把余量塞进末窗（262144→268127 触发 400；258048 档
  也有 1/4 序列超限），只可用于形状粗筛。**准入票的标准量尺 = `reburst_max.py 261872 4`**：
  经 `count_tokens` 把每条 prompt 精确拟合到合法深度，四行全有效。**target 必须留 gen 头寸**：
  B 段 prompt+`LB_GEN_B`(256) 也要进窗——262136 会把解码剪成 8 token 的退化档（聚合口径失效，
  2026-11-28 07:56 一轮因此作废重跑）；261872 = ctx − 256 − 16 才是标准位。配合每臂
  `rm -rf /data/cache/conv-tier-fresh` 的空冷层，才是可比对。驱动：`wb_max.sh`
  （M0 off / M2 3×full / M1 2×full）。
- **一次碰撞的账**：该轮 `fill_errs=1 / dec_errs=1`。其一在 boot 期（budget 生效前，无责）；
  其二是 B 段后 `copy_states` 被并发抢占瞬时挤压，走向 `Placement::Failed` → 客户端 400。
  **`a8009bf`** 把它改成 `Placement::Retry`：放置已完整回滚（表释放、ring/slot 归还、预约退回），
  作业重新入队、下一步再放置一次；`Job::place_retry` / `Seq::place_retry` 限定只重试一次，
  确定性失败照样报错。`resume()`（抢占复活）同一形状，瞬时碰撞不再打断在跑的对话。
- **P2 的填缝需求（尚未定标）**：dev 道（2 卡，budget 131072/196608）里同尺寸深行只有 2 行进窗，
  其余排队至 **488 s** 才靠 starve 兜底进窗——机制正确，但"小请求能否绕过大请求填空缝"在混排负载
  下从未实测。`pop_fit` 已具备 `Fits` 跳过能力（跳过 `Blocked` 候选继续扫），外层 while 的 slot
  条件是唯一的门，所以 bin-pack 填缝是纯调度层改动，验收场景 = 1 条满窗 + N 条小窗。
- **裁决口径**：收益只在 4 卡以上可测（2 卡 64K 每行本就超供给带宽 §416，且排队行的前缀被洗掉后
  B 轮重算 pp 81-170 s），dev 道只验机制不死。
